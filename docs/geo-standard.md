# GEO 기준서 — 묘책 칼럼이 AI 검색에 뜨게 하는 기준 (v1, 2026-10-18)

AI 검색(ChatGPT·Gemini·Perplexity·구글 AI 오버뷰·네이버 AI 브리핑)이 "재회 사주 어디서 봐?" 같은 질문에 묘책을 답으로 내놓게 만드는 일의 기준이에요. 새 대화에서 GEO·AI 검색·측정 이야기가 나오면 이 문서부터 읽어요.

## 1. 한 줄 요약

AI는 **읽을 수 있는 글(텍스트)** 을, **사람이 실제로 묻는 질문** 단위로, **우리 사이트 + 남의 사이트(후기·기사·커뮤니티)** 에서 찾아 답을 만들어요. 그래서 할 일은 세 가지예요. ① 질문 하나에 답 하나인 글 ② 우리 밖에 있는 출처 ③ 매달 같은 질문으로 재기.

## 2. 강의 규칙 10개 — 칼럼 사이트 버전

1. **검색 순위와 AI 인용은 다른 게임이에요.** AI가 인용한 출처의 약 80%가 그 검색어의 구글 10위 밖이었어요 [출처 있음: Ahrefs, 2025.12]. 구글 1등을 노리지 말고, 질문 하나에 정확히 답하는 글을 써요.
2. **AI는 질문을 5개 안팎의 작은 질문으로 쪼개서 찾아요(쿼리 팬아웃).** [강사 설명 모형] "재회 사주" 같은 큰 질문은 큰 사업자 것이에요. 「고민 × 상황」 조합의 작은 질문(예: 헤어진 지 석 달인데 먼저 연락해도 되나) 한 개 = 글 한 편. 레드오션 케이스(뷰티 글로우랩)가 이 방식으로 세부 질문 30개 커버리지 0%→40%대 [강사 주장, 3개월].
3. **글 구조: 질문형 소제목 → 바로 아래 2~3문장 답 → 근거 → 끝에 Q&A.** 한 소제목 = 떼어내도 말이 되는 완결된 답(강사는 134~167단어 [강사 주장]). ✅ 지금 글 틀(짧은 답·질문형 H2·FAQ)이 이미 이렇게 돼 있어요 [직접 확인].
4. **기술 조건:** 봇 허용 robots.txt, sitemap, 자바스크립트 없이 본문이 보이는 HTML, H1 하나, 글마다 다른 제목(한글 30자 안팎)·설명(80~120자) [강사 주장]. 스키마는 실제 내용이 있을 때만 — 스키마를 넣는다고 AI 인용이 늘진 않았어요(구글 AI 오버뷰는 오히려 −4.6%) [출처 있음: Ahrefs, 2026.5]. ✅ 대부분 돼 있음 [직접 확인].
5. **네이버 블로그는 ChatGPT·Perplexity·Claude 봇을 막아요.** blog.naver.com/robots.txt에 GPTBot·OAI-SearchBot·PerplexityBot·ClaudeBot·Claude-SearchBot·Google-Extended·meta-externalagent·Applebot-Extended·CCBot 차단 [직접 확인 가능]. 구글·네이버 AI 경로는 열려 있어요. → 칼럼 사이트가 "AI용 블로그", 네이버 블로그는 구글·네이버용. 복사하지 말고 다시 써서 칼럼 링크(CLAUDE.md 대기 7번과 같음).
6. **우리 사이트에만 있는 말은 AI가 잘 안 믿어요.** 인용의 과반은 다른 도메인·권위 매체에서 온다는 게 강의의 핵심 주장 [강사 주장, ChatGPT 시스템 프롬프트 유출 추정본 근거]. 보도자료 와이어 뿌리기는 인용 0.2% [출처 있음: Meltwater, 2026.05], 종합지보다 그 주제 전문매체가 더 인용됨(전문매체 45% vs 종합일간지 16%) [출처 있음: 신문과방송 2025.11, 한국언론진흥재단]. → 실제 후기를 읽을 수 있는 곳 3~5곳에, 사주·연애 주제 전문매체 1건, 기사·후기는 자사 사이트에 모아 두기.
7. **사주는 삶에 영향을 주는 주제라 신뢰 신호(E-E-A-T)가 더 필요해요.** 실명 검수자(✅ 있음) + **검수자가 누구이고 어떤 기준으로 보는지**(⚠️ 없음) + 검토일 + 우리만 가진 1차 자료. 효과 보장·최상급·지어낸 경험담은 처음부터 쓰지 않아요(정형외과 케이스 원칙).
8. **구글이 벌주는 것:** 검수 없는 대량 발행, 복붙, 숨긴 글자, 가짜 후기, AI에게만 보이는 숨김 지시문 [출처 있음: 구글 스팸 정책 문서 2026.05.15 기준, AI 오버뷰·AI 모드에도 적용]. "AI가 초안, 사람이 책임". ✅ 승인·검수자 없이는 발행이 안 되는 장치가 이미 있어요 [직접 확인].
9. **인스타·스레드는 AI 인용 재료가 아니에요.** AI가 인용한 소셜 출처 중 인스타그램 2.2%, 스레드 0.1%, 레딧 46.4%, 유튜브 31.8% [출처 있음: OtterlyAI 2026]. 릴스는 고민 수집·확산용, 글은 칼럼에. 유튜브는 10~20분 롱폼을 "챕터 = 질문, 구간 = 답"으로 만들면 구글 AI에서 강함 [강사 주장].
10. **측정 없이는 좋은지 나쁜지 알 수 없어요.** AI는 노출 숫자를 안 줘요. 같은 질문 묶음을 매달 반복해서 「몇 개 질문에 묘책이 나오나(질문 커버리지율)」「답의 출처 링크에 우리 도메인이 있나(인용)」를 세요. 최소 세트: 질문 50개·ChatGPT 1개·월 1회 [강사 권장]. 1~2주 만에 판단하지 말고 2~3번 잰 뒤 추세로.

## 3. 2026-10-18 진단 (강의 체크리스트 기준)

**✅ 이미 돼 있는 것** [직접 확인 — 저장소 코드·빌드 결과·공개 사이트]
- robots.txt에서 GPTBot·OAI-SearchBot·ChatGPT-User·PerplexityBot·ClaudeBot·Claude-SearchBot·Google-Extended·Applebot-Extended·Yeti·Daumoa 허용
- sitemap.xml(27 URL), feed.xml, llms.txt(브랜드 정의 문장 포함), IndexNow
- 정적 HTML — 본문이 자바스크립트 없이 그대로 읽힘, 글 한 편 본문 약 5,500자
- H1 하나, 질문형 H2, 맨 위 「짧은 답」(answer-first), FAQ 3개 이상
- 스키마: Organization(푸터와 같은 값)·WebPage(reviewedBy 검수자)·Article·BreadcrumbList·FAQPage
- 검수자 실명, 실제 고민 출처(플랫폼·날짜), 지어낸 후기 없음(후기 칸은 비어 있으면 숨김)
- canonical, 검색용 제목 30자 규칙, 브랜드 정의 문장(본 사이트와 동일), 서치콘솔·GA4 연결
- 발행 안전장치: 승인·검수자·실제 고민·상품 링크 없으면 발행 안 됨

**⚠️ 빠진 것 / 약한 것**
1. **본 사이트(www.myocheck.kr) → 칼럼으로 가는 링크가 0개.** 메뉴·푸터 어디에도 없음. 본 사이트는 상품명조차 텍스트로 안 보이는 페이지라(이미지·JS), 강의가 말한 "양방향 링크"가 한쪽만 있음.
2. **측정 0회.** AI에 묘책이 나오는지 한 번도 재지 않음.
3. **우리 밖 출처 0.** 후기·기사·커뮤니티 언급 없음.
4. **사주 전문성이 얇음.** 글은 연애 상담 + 「사주로 보면」 3~4줄. 저자 "묘책 편집팀", 소개 페이지는 "디식주의자에서 만들어요"뿐 — 검수자가 누구이고 왜 믿을 만한지 없음.
5. **공개 12일째.** 강의 기준 단기 효과 1~2개월, 장기 수개월 [강사 주장]. 지금 결과로 판단할 시점이 아님.
6. 작은 것: 이미지 대체문구(alt) 빈 것 4개, 검색 설명문 72자(기준 80~120).
7. 궁합 글 0편(분류 페이지는 sitemap에서 빠지게 처리돼 있어 문제는 아님).

## 4. 할 일 순서 — "끝났다"의 기준까지

① **측정 세트 50문 + 첫 측정** (가장 먼저)
- 질문은 지어내지 않아요. `research/`·DM·댓글·수집함의 실제 문장을 "묘책을 모르는 사람이 AI에 칠 문장"으로 다듬어요.
- 배분(강의 100문 표를 반으로): 정보 탐색 10 / 대안 찾기 17 / 비교 10 / 구매 결정 8 / 상황 특화 5. 브랜드명 없는 질문 70% 이상.
- 한 번 정하면 분기 단위로만 고치고 버전(v1.0, v1.1)을 적어요. 새 질문은 따로 추적하다 다음 분기에 편입.
- 측정: ChatGPT 임시 채팅, 질문당 3회, 날짜 박힌 답변 캡처. 세는 것 둘만 — 커버리지(50개 중 묘책이 한 번이라도 나온 질문 수)와 출처 도메인 목록(어떤 사이트가 뜨나).
- 끝났다: 시트 3장(대시보드 / 원본데이터 / 질문세트 v1.0) + 첫 커버리지 % + 출처 도메인 상위 10개. 대시보드 맨 아래에 산식·기간·세트 버전 명기.
- 빈칸 질문 목록 = 다음 달 글감. 출처 도메인 목록 = 후기·글을 실을 곳.

② **본 사이트 → 칼럼 링크** (사장님 확인 필요)
- 사이더사주 관리 화면에서 메뉴·푸터에 링크를 넣을 수 있는지 사장님이 확인. 본 사이트는 보기만, 클로드가 바꾸지 않음.
- 끝났다: www.myocheck.kr 어딘가에 column.myocheck.kr 링크 1개 이상. 안 되면 ④의 상품 텍스트판을 칼럼 안 메뉴로만 연결.

③ **검수자·전문성 소개**
- `about` 페이지에 검수자가 누구이고(실명), 사주를 어떤 기준으로 보는지(review-guide의 원칙을 사람 말로), 검토·수정은 어떻게 하는지. 사실만, 자격·경력을 꾸미지 않음.
- Person 스키마는 페이지에 실제 내용이 생긴 뒤에만.
- 끝났다: about에 검수자 소개 문단 + 글 하단 "검수 공혜선"이 그 문단으로 링크.

④ **상품 텍스트판 3장** (라이브 상품: 재회막차·인형의 방·2027 신년운세 등 products.yml 기준)
- 강의 "통이미지 상세페이지 해결책 ②"가 바로 이것. 상품 하나당 칼럼 사이트에 텍스트 한 장: 상품명(공식 표기) / 한 줄 정의("○○은 ~를 내 사주로 읽는 맞춤 리포트입니다" — AI가 그대로 복사할 문장) / 이런 분이 봅니다(실제 고민 3개) / 입력하는 것 / 결과지 구성(products.yml toc 그대로) / 담당 캐릭터 / 가격·소요 시간 / Q&A 4~5개 / 검수자·검토일 / 상품 버튼.
- 끝났다: 3장 공개 + 각 칼럼의 상품 버튼 옆에 "자세히" 링크 + (②가 되면) 상품 페이지에서 텍스트판으로 오는 링크.

⑤ **리뷰 가이드 질문** (결제 후 DM·카톡채널)
- 세 가지만 묻기: 어떤 고민으로 봤나 / 어떻게 봤나(상품·캐릭터 이름 그대로) / 뭐가 달라졌나. 대본을 주지 않고 질문만. 단점도 환영.
- 실제 후기만 products.yml `reviews`에. 빈 칸은 비워 둠(지금처럼).
- 끝났다: DM 문구 확정 + 첫 실제 후기 1건.

⑥ **4주 루틴을 캘린더에**
- 1주 측정(캡처 모으기) → 2주 보고 1장(한 줄 결론 + 빈칸 질문 목록) → 3주 기존 글·상세 손보기 → 4주 빈칸 질문에 답하는 글 발행.
- 못 지키면 우선순위 **측정 > 분석 > 발행 > 개선**. 측정이 끊기면 전부 무효.
- 끝났다: 반복 일정 4개 등록 + 첫 달 보고 1장.

그다음(2개월 차): 사주·연애 전문매체에 보도자료 1건(노션의 보도자료 프롬프트 사용, 없는 숫자는 [통계 필요]로 비움, 자사 뉴스룸=칼럼에 아카이브) / 릴스 6~8편을 묶어 10~15분 롱폼 1편(챕터 = 질문, 교정 자막, 설명란에 칼럼 링크).

## 5. 하지 말 것 · 주의

- **ChatGPT 광고는 지금 보류.** OpenAI 광고 정책 v1.6(2026-09-10) 기준 사주·점술은 금지 목록에 없지만, 데이트 앱 금지·미국 밖 금융/건강/법률 금지·"감정적으로 의존하는 대화, 정신·개인 건강 대화"에는 광고를 붙이지 않음. 재회·이별 고민 대화가 그 범주일 가능성이 큼(추측). 강의 결론도 "Organic GEO 먼저".
- 출처 없는 강사 숫자(GEO 유입 전환율 15~20%, 월 발행 8~15건, 리뷰 30건 등)는 우리 보고서에 쓰지 않아요.
- 강의 슬라이드·프롬프트·PDF를 이 공개 저장소에 올리지 않아요(수강생 공유 자료).
- 측정 숫자는 도구·질문 세트·시점이 다르면 비교하지 않아요. 바꿀 때는 이유와 날짜를 적고 새 기준선을 세워요.

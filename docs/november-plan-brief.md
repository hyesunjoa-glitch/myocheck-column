## 꼭 지킬 것
- 파일: `content/columns/<slug>.md` 새로 만들기. `status: 초안`, `reviewer:` 비움, `date: 2026-10-27`. **다른 글·site.yml·build.py는 건드리지 않기. git 커밋 금지.**
- 글 구조는 예시와 똑같이: title / seo_title(30자 이내, 검색어 앞쪽) / subtitle / slug / category / product / character / report_chapter / cover_say(formal·casual) / situations(3개, go:는 본문 소제목 번호 — 1부터 셈) / next_questions(2개, 아래 23편 목록이나 이미 있는 글 제목에서) / keywords(검색어 그대로 5~8개) / status / date / reviewer / summary(짧은 답 2~3문장, 결론부터) / description(80~120자) / concerns / faq(3개) / saju(3~4줄) / cta_line.
- 본문: 질문형 소제목(H2) 6~7개, 각 소제목 바로 아래 첫 2~3문장이 답. `[[상품버튼]]` 1번, `[[사주해석]]` 1번, 캐릭터 말풍선 2~3번. 비교 성격이 있으면 「…, 한눈에 비교하면요?」 표(칸은 본문에 쓴 내용만).
- **concerns(실제 고민)**: 지어내지 않음. 사람이 쓴 글(스레드·유튜브 댓글·아하)은 research 파일 원문에서 잘라 40자 안팎, 고쳐 쓰지 않고 ' … '로 잇기. 표기 `source: 스레드, 2026년 10월`처럼 플랫폼+날짜만(채널·계정명·링크 금지). 사람 글이 없으면 구글 자동완성 줄을 `"2027 삼재띠 / 2027년 삼재 나이"`처럼 넣고 `source: 구글 자동완성, 2026년 10월`.
- 사람 글을 인용했다면 그 원문·링크를 보고서에 적어 주기(나중에 research/concern-sources.yml에 넣음).
- 근거 없는 숫자·「~한 분들이 많아요」「대부분」「가장 많이」 금지. 후기·사례·통계 지어내기 금지. 설명용 상황은 「예를 들어」로만.
- 사실(날짜·풍속·계산법)은 확실한 것만. 헷갈리면 WebSearch로 확인하고 출처를 보고서에 적기. 확인된 사실: 2027년 = 정미년(양띠), 사주의 새해 = 입춘 2027년 2월 4일(오전 10시 46분쯤), 설날 2027년 2월 7일. 삼재: 돼지·토끼·양띠는 뱀·말·양의 해(2025·2026·2027)가 삼재 → 2027년은 이 세 띠의 날삼재(나가는 삼재, 마지막 해). 들삼재(첫해)·눌삼재(둘째 해)·날삼재(셋째 해).
- 우리 입장: 「남 얘기 같은 띠 운세 말고, 내 사주로 읽는 맞춤 리포트」. 띠·삼재·토정비결 글도 **검색한 질문에는 먼저 정확히 답하고**, 그다음 「띠는 사주 여덟 글자 중 하나」처럼 내 사주로 이어 줌. 겁주기·부적 권하기·결과 약속 금지.
- 「사주로 보면」(saju:) 3~4줄: 사주 용어 0개(대운→10년 흐름, 세운→그해 흐름, 합/충→묶이는/부딪히는 때 등). 마지막 줄은 상품으로 이어 주되 약속 없이.
- 제목·keywords에 검색어(삼재·대운·원진살 등)가 들어가는 건 괜찮음. 본문에선 처음 한 번 쉬운 말로 풀어 줌.
- 말투: 괴짜Z(신년) = 괴짜스러운 존댓말(예시 글 말풍선 참고), 이설(궁합) = 따뜻한 언니 존댓말, 묘화(재회) = 존댓말. 본문 문장도 존댓말 「~해요」체. 한 문장은 한 번에 읽히게 짧게. 한자 금지.
- cta_line: 그 글 제목에 맞춘 한 줄(하루 단위 날짜 약속 금지 → 「시기」로).
- 다 쓰면 스스로 1차 검수: 금지 표현 찾기, 사주 용어 찾기, go: 번호 맞는지, saju 줄 수. **약한 곳은 고쳐서** 끝내기.
